# SmartDash — цифровой прибор Honda Dunk AF78 на ESP32-S3

## Описание

SmartDash — компактный дополнительный прибор для мотоцикла на базе платы **JC3636W518C** (ESP32-S3, круглый IPS-дисплей 360×360, ёмкостный тач). Прибор подключается по Bluetooth LE к ELM327-совместимому адаптеру, считывает данные OBD-II и отображает скорость, обороты, температуру и напряжение в круглом интерфейсе.

Текущее состояние зафиксировано: сплошная дуга оборотов с отдельной внутренней шкалой. Это рабочая версия интерфейса, к которой пришли после нескольких итераций по сегментам и рискам.

## Статус реализации

- [x] Инициализация дисплея ST77916 (QSPI) и тача CST816S (I²C)
- [x] Полноэкранный буфер в PSRAM — отрисовка без мерцания
- [x] Одноразовая стартовая анимация вместо бесконечного демо
- [x] Сплошная дуга RPM 0–12000 с зонами 8000 / 10000 об/мин
- [x] Отдельная внутренняя шкала: риски каждые 1000, цифры каждые 2000 об/мин
- [x] Скорость 0–99 крупными семисегментными цифрами; `0` всегда по центру
- [x] Температура и напряжение с цветовой индикацией
- [x] Индикатор ELM: три мигающие точки при поиске, `ELM OK` при подключении
- [x] BLE ELM327: поиск, автоподключение к последнему устройству, инициализация и опрос
- [x] Экран **ELM Monitor**: до подключения — список найденных адаптеров, RSSI и подключение по тапу (устройства отсортированы по убыванию RSSI); после подключения — имя, адрес, протокол и время работы активного адаптера
- [x] Навигация: свайп вверх с Dash открывает ELM Monitor, вниз с Dash — экран настроек (read-only); вниз с ELM и вверх с настроек — назад; влево/вправо — Dash ↔ Drag
- [x] Экран замера разгона с места: ожидание холостых 1500–2500 об/мин, таблица 10–100 км/ч, завершение по сбросу оборотов; данные только от ELM или из тестового режима `sim`
- [x] Последний и лучший замер сохраняются в NVS и пишутся в журнал подключений
- [x] Wi-Fi AP с корневой страницей, формой настроек `/settings` и отдельной страницей журнала `/log`; в одном тёмном стиле, с крупными кнопками для телефона
- [x] Веб-форма настроек: RPM max/redline, пороги температуры и напряжения, стартовая анимация, название модели — сохранение в NVS
- [x] Captive portal: телефон сам открывает корневую страницу после подключения к AP
- [x] Кнопка WEB на экране Settings включает/выключает AP, DNS и HTTP; состояние сохраняется в NVS, по умолчанию выключено
- [ ] Остальные параметры (единицы, цвета зон, настройки Drag/ELM) — инвентарь в `docs/SETTINGS.md`
- [ ] Фильтрация выбросов и таймаут обновления данных
- [x] Проверка с реальным ELM327: подключение, инициализация и приём данных подтверждены

> Без ELM прошивка работает стабильно, повторяет поиск каждые несколько секунд и показывает нули после стартовой анимации. Скорость обновления показаний оптимизирована: быстрые PID запрашиваются одним запросом, а на панель выводятся только изменившиеся области спрайта.

## Целевая платформа

| Параметр | Значение |
|---|---|
| Плата | JC3636W518C / ESP32-S3 Display Module |
| MCU | ESP32-S3R8, 240 МГц, Wi-Fi + BLE 5.0 |
| Дисплей | 1.8" круглый IPS, 360×360, ST77916, QSPI |
| Тач | CST816S, I²C, адрес `0x15` |
| Питание | Type-C (на мотоцикле — через DC/DC 12 В → 5 В) |
| Мотоцикл | Honda Dunk AF78 |
| Диагностика | Honda 4-pin → OBD2 переходник → BLE ELM327 |
| Красная зона | 8000 об/мин |
| Максимум шкалы | 12000 об/мин |

ESP32-S3 **не поддерживает Bluetooth Classic**, поэтому нужен именно BLE-совместимый ELM327.

## Что отображается

### Обороты

Внешняя дуга — сплошная, без сегментных просветов:

- угол: от **150°** до **390°** (240° всего);
- радиусы: **160–176 px**;
- подложка: тёмно-серый `0x2104`;
- зоны закраски:
  - `0–8000` — зелёный;
  - `8000–10000` — оранжевый;
  - `10000–12000` — красный.

Внутренняя шкала отделена от дуги и не перегружает отображение:

- тонкая опорная дуга радиусом **150 px**;
- риски каждые **1000 об/мин**, радиусы **138–150 px**;
- подписи каждые **2000 об/мин**: `0, 2, 4, 6, 8, 10, 12`;
- подписи означают тысячи об/мин.

### Скорость

- диапазон **0–99 км/ч**;
- крупные семисегментные цифры белым цветом, неактивные сегменты — тёмно-серые;
- значения `0–9` рисуются **одной цифрой по центру**, поэтому `0 км/ч` не смещается влево;
- подпись единиц — `km/h`.

### Температура и напряжение

Внизу экрана две колонки с иконками:

| Параметр | Условие | Цвет |
|---|---|---|
| Охлаждающая жидкость | `< 60 °C` | голубой |
| | `60–90 °C` | зелёный |
| | `> 90 °C` | красный |
| Напряжение | `< 11 В` | красный |
| | `11–12 В` | оранжевый |
| | `12–15 В` | зелёный |
| | `> 15 В` | красный |

Если данных нет, показывается `--C` и `--.-V`.

### Стартовая анимация и статус ELM

При включении, если ELM ещё не подключён, выполняется **один** пробег:

- RPM: `0 → 12000 → 0`;
- скорость: `99 → 0`;
- температура: `99 → 0` шагом 5;
- напряжение: `16.0 → 0` шагом 0.5 В.

Затем все значения остаются нулями до данных от ELM. Данные от реального адаптера немедленно перекрывают анимацию.

В нижней части экрана:

- при подключении — зелёная надпись `ELM OK`;
- без подключения — `ELM` и три оранжевые точки, загорающиеся по очереди;
- рамка вокруг индикатора отсутствует.

## Управление

| Действие | Результат |
|---|---|
| Свайп снизу вверх с Dash | Открыть экран ELM Monitor (поиск/подключение идут в фоне); с Drag игнорируется |
| Свайп сверху вниз с Dash | Открыть экран настроек (только просмотр) |
| Свайп сверху вниз с ELM Monitor | Закрыть ELM Monitor и вернуться на предыдущий экран |
| Свайп снизу вверх с Settings | Закрыть экран настроек и вернуться на Dash |
| Свайп влево / вправо | Переключить Dash ↔ Drag; на ELM Monitor и Settings игнорируется |
| Кнопка BOOT | Закрыть ELM Monitor / Settings или переключить Dash ↔ Drag |
| Тап по кнопке `WEB OFF` на экране Settings | Включить Wi-Fi AP, DNS и веб-сервер (состояние сохраняется) |
| Тап по кнопке `WEB ON` на экране Settings | Выключить веб и полностью снять радио Wi-Fi |
| Подключиться к Wi-Fi `SmartDash-<id>` | Открыть корневую страницу; тап `SETTINGS` ведёт в форму, `ELM LOG` — в журнал |
| Тап по `Scan` | Отключиться от текущего ELM и начать новый поиск BLE-устройств |
| Тап по устройству в списке | Подключиться к выбранному ELM327 (только когда соединения нет) |

Свайп определяется во время движения пальца: порог 60 px, длительность до 1 с. Оба вертикальных жеста начинаются с Dash: вверх открывает ELM Monitor, вниз — настройки; с ELM Monitor вниз возвращает назад, с настроек вверх — на Dash. На Drag вертикальные свайпы не действуют. Горизонтальные переключают Dash ↔ Drag, на модальных экранах и при диагонали игнорируются. После обработанного свайпа тап подавляется, чтобы случайное нажатие не меняло состояние.

Экран **ELM Monitor** ведёт себя по-разному в зависимости от состояния. Пока соединения нет, он показывает статус поиска/подключения и список найденных BLE-устройств. После завершения AT-инициализации вместо списка выводятся данные активного адаптера: имя, BLE-адрес, тип адреса (Public/Random), протокол (`KWP fast`, `KWP slow`, `Auto`), уровень сигнала и время соединения. Само открытие экрана поиск не запускает: для смены устройства служит кнопка `Scan`, тапы по области списка при подключённом ELM игнорируются. Имя адаптера сохраняется в NVS вместе с адресом, поэтому доступно и после перезагрузки, когда подключение идёт прямо по сохранённому MAC без сканирования (RSSI в этом случае неизвестен).

Экран **Settings** показывает десять текущих значений и кнопку `WEB ON/OFF` — редактировать поля на приборе неудобно, поэтому правки идут через смартфон. Wi-Fi по умолчанию выключен: тап по `WEB OFF` поднимает AP `SmartDash-<id>`, DNS captive portal и HTTP-сервер, тап по `WEB ON` останавливает сервер, DNS и полностью снимает радио. Состояние пишется в NVS (`cfg_web_enabled`) и восстанавливается при загрузке.

После подключения к AP телефон открывает корневую страницу в том же тёмном стиле: две крупные кнопки `SETTINGS` и `ELM LOG`. На `/settings` те же десять полей (`RPM MAX` 6000–16000 шагом 1000, `REDLINE` 4000…RPM MAX−2000 шагом 500, `COOL LOW/HIGH` 40–140 °C шагом 5, `VOLT LOW/MID/HIGH` 9–18 В шагом 0.5, `ROTATION` 0/90/180/270°, `BOOT ANIM`, `MODEL` до 19 символов) с крупным вводом и кнопкой `SAVE`. Сервер проверяет диапазоны и порядок порогов через `settings_normalize()`, пишет NVS под ключами `cfg_*` и уведомляет UI: дашборд перерисовывается целиком, а экран Settings обновляет значения. Дефолты берутся из `include/config.h`. Выключение `BOOT ANIM` действует сразу, включение и новое `MODEL` — после перезагрузки. `ROTATION` применяется сразу: панель поворачивается аппаратно (только кратные 90°), тач и свайпы пересчитываются LovyanGFX в новой системе координат, экран перерисовывается целиком. На `/log` — отдельная страница журнала с кнопками просмотра хвоста, полного файла и очистки;текст по-прежнему отдаёт `/elm-log`. Полный инвентарь остальных параметров — в `docs/SETTINGS.md`.

Экран **Drag** включается сразу при входе: сначала ждёт устойчивые холостые (1500–2500 об/мин не менее 0.8 с), затем ждёт скачка оборотов и начала движения. Отсчёт идёт от интерполированного пересечения скорости 3 км/ч, а не от скачка оборотов — газовка на месте замер не запустит. Сэмпл OBD привязан к середине интервала запрос→ответ; его границы пишутся в журнал как `DRAG S t=... tx=... rx=...`. Пересечение каждой отметки 10 км/ч ищется интерполяцией между сэмплами. Замер завершается либо на выбранной цели, либо по сбросу оборотов: в результате остаётся последняя достигнутая отметка. Лучший результат хранится отдельно для каждой скорости. Синтетической рампы больше нет — экран работает только с сэмплами ELM или тестового режима `sim` (команды `sim rpm=... spd=...` через USB Serial).

## BLE и ELM327

Вся BLE-работа вынесена в отдельную задачу FreeRTOS `elmTask` на **core 0**. Основной цикл (`loop()`) занимается только UI и веб-сервером, поэтому сканирование и подключение не замораживают экран и тач.

### Последовательность инициализации ELM

```
ATZ
ATE0
ATL0
ATS0
ATH0
ATSP5   -> 0100   (ISO 14230-4 KWP, fast init)
ATSP4   -> 0100   (ISO 14230-4 KWP, slow init / 5 baud)
ATSP0   -> 0100   (автоопределение, запасной вариант)
```

Следующий протокол пробуется только если `0100` не вернул ответ `41 ...` (`STOPPED`, `ERROR`, `NO DATA` или таймаут). `ATZ` получает таймаут 2.5 с, базовые AT-команды — 1.2 с, `0100` — 6–8 с, поскольку KWP-инициализация у клонов ELM327 идёт медленно. Адрес сохраняется в NVS только после подтверждённого `0100`.

### Цикл опроса

Быстрая пара — обороты и скорость — запрашивается одним запросом и не ждёт медленных параметров:

```
010C0D   -> 410C A B 410D C
              RPM = (A * 256 + B) / 4
              Speed = C
```

`0105` (температура) и `ATRV` (напряжение, принимается 5–20 В) чередуются отдельными запросами раз в секунду, то есть каждый параметр обновляется раз в 2 с. Медленные параметры не вытесняют быстрые запросы. Приглашение `>` в конце ответа уже означает готовность адаптера, поэтому дополнительная пауза не выдерживается: следующий запрос уходит на следующем такте задачи (~2 мс). Если клон отвечает по таймауту или без `41 0C`, пауза автоматически удваивается (8→16→…→120 мс), а после ~2 с чистых ответов снова уменьшается. Ответы парсятся по hex-шаблону `41 <PID>`; на экране остаётся последнее удачно полученное значение.

Если адаптер не поддерживает несколько PID в одном запросе, после трёх ответов без `41 0C` драйвер автоматически переходит к прежнему раздельному опросу `010C / 010D / 0105 / ATRV` (медленнее, но совместим с любым клоном). Это событие пишется в журнал как `POLL multi-PID unsupported -> legacy ...`.

Ожидаемая частота оборотов/скорости — 5–10 Гц и выше, в зависимости от адаптера и протокола; температура и напряжение — 0.5 Гц.

### Подключение

- Имя устройства считается совместимым, если содержит `OBD`, `ELM`, `V-LINK`, `VEEPEAK`, `OBDLINK` или `VGATE`.
- Дополнительно проверяются UUID `FFF0`, `FFE0`, `6E400001`.
- Для UART-профиля ищутся `FFF1`/`FFF2` или Nordic UART Service.
- Адрес успешного устройства сохраняется в NVS (`smartdash` / `last_elm`).
- При старте сохранённый адрес используется для autoconnect; если его нет — запускается сканирование.
- При потере связи поиск перезапускается с интервалом 3 с; после трёх неудач подключения к сохранённому MAC (`setConnectTimeout` в NimBLE задаётся в мс) прошивка переходит к поиску любого совместимого адаптера.

`rxBuf`, список найденных устройств и данные активного соединения защищены мьютексами, так как обновляются из BLE-задачи, а читаются из UI. Список `found` хранится отсортированным по убыванию RSSI: при каждом обновлении запись сдвигается вверх или вниз, поэтому первые строки экрана — всегда устройства с самым сильным сигналом. `ElmConnectedInfo` вытягивается в UI через `elm_get_connected()` и показывается только после завершённой AT-инициализации — во время поиска экран по-прежнему показывает список.

### Журнал подключений

Журнал пишется в файл на флэше (LittleFS, раздел `spiffs` из `default_16MB.csv`), поэтому спокойно переживает поездку, выключение питания и перезагрузку. Текущий файл `/elm.log` растёт до **1 МБ** (~5–6 тыс. строк), затем становится `/elm.prev.log`, и начинается новый файл — суммарно хранится до ~2 МБ истории. Формат строки: `b<номер загрузки> t<секунды>.<мс> <событие>`. Пишутся `BOOT`, `SCAN`, `MATCH`, `CONNECT`, `GATT`, `CHARS`, `AT`, `PROTO`, `INIT`, первые 8 ответов опроса и неудачи по сохранённому MAC.

Просмотр после возвращения к ПК:

- **По USB:** подключитесь, откройте монитор порта (115200) и введите `log` — последние 16 КБ; `log all` — весь журнал; `clear` — очистить. При старте печатается подсказка. Чтение идёт порциями, поэтому запись новых событий не блокируется надолго.
- **По Wi-Fi:** страница `http://192.168.4.1/log` с кнопками; текстовые эндпоинты `http://192.168.4.1/elm-log` — хвост 32 КБ, `.../elm-log?all=1` — весь файл, `?clear=1` — очистить с возвратом на `/log`.

Номер загрузки `bN` позволяет отличить события до и после перезапуска. Журнал не зависит от `SMARTDASH_SERIAL_DEBUG`: он пишется всегда и остаётся в файле даже если питание выключилось сразу после события.

```
smartdash/
├── platformio.ini        #Конфигурация PlatformIO
├── include/
│   ├── config.h          # Пины, константы экрана и мотоцикла
│   ├── display.h         # Интерфейс LovyanGFX
│   ├── dragrace.h        # Конечный автомат замера разгона
│   ├── elm327.h          # Публичный API BLE/ELM
│   ├── settings.h        # Пользовательские настройки в NVS
│   ├── storage.h         # NVS + журнал на LittleFS
│   ├── ui.h              # Данные дашборда и UI-API
│   └── web.h             # Wi-Fi AP / WebServer
├── src/
│   ├── main.cpp          # setup()/loop()
│   ├── display.cpp       # Настройка ST77916, подсветки и CST816S
│   ├── dragrace.cpp      # Холостые -> старт -> отметки 10 км/ч -> результат
│   ├── elm327.cpp        # BLE-задача, AT-команды, парсинг PID
│   ├── settings.cpp      # Загрузка/сохранение настроек, ограничения значений
│   ├── storage.cpp       # Последний ELM, замеры, журнал подключений
│   ├── ui.cpp            # Рендер, анимация, тач/свайпы, экраны
│   └── web.cpp           # AP, корень, формы /settings и /log, выгрузка /elm-log
├── docs/                 # Заметки по разработке (SETTINGS.md — инвентарь настроек)
└── README.md
```

Потоки данных:

```
ELM327 (BLE) -> elmTask (core 0) -> DashData+t_ms -> snapshot -> ui_loop() (core 1) -> PSRAM sprite -> display
                                      \-> dragrace.cpp (сэмплы, отметки, результат) -> NVS/журнал
```

Статические элементы шкалы рисуются один раз. Динамические элементы перерисовываются только при изменении значения (для напряжения — с порогом 0.05 В). При изменении оборотов заливается не вся дуга, а только изменившийся участок; подпись `km/h` тоже относится к статике и при смене скорости не перерисовывается.

На панель выводятся не весь кадр 360×360, а только «грязные» прямоугольники: clip-область выставляется на дисплее, затем `pushSprite()` отдаёт из спрайта нужный кусок. Полный кадр используется только при смене экрана и после перерисовки статики. Экран ELM Monitor обновляется не чаще одного раза в 600 мс, так как его полный вывод занимает около 50 мс.

## Сборка и прошивка

```bash
# Сборка
~/.platformio/penv/bin/pio run

# Сборка + заливка (порт определяется автоматически)
~/.platformio/penv/bin/pio run -t upload
```

Порт обычно `/dev/ttyACM0`. Если Linux не видит устройство пользователю, нужен `dialout` или правила udev PlatformIO.

Логирование по умолчанию отключено: `Serial.printf` через USB CDC иногда блокировал задачу почти на 800 мс. Чтобы включить логи, добавьте в `build_flags` в `platformio.ini`:

```
-DSMARTDASH_SERIAL_DEBUG=1
```

`pio device monitor` требует интерактивного терминала; при перенаправлении вывода используйте любой обычный последовательный монитор.

## Wi-Fi

Точка доступа поднимается только после тапа по кнопке `WEB OFF` на экране Settings и хранит это состояние в NVS:

- SSID: `SmartDash-<последние 4 байта efuse>`;
- пароль: `smartdash`;
- адрес: `http://192.168.4.1`.

Корневая страница `http://192.168.4.1/` — точка входа: кнопки `SETTINGS` (`/settings`) и `ELM LOG` (`/log`), страницы оформлены в одном стиле. Включён captive portal: DNS отвечает адресом прибора на любые имена, а проверки интернета (`/generate_204`, `/hotspot-detect.html`, `/connecttest.txt` и др.) редиректят на корень, поэтому при подключении к сети телефон должен сам открыть страницу. Если ОС не показывает вкладку автоматически, откройте `http://192.168.4.1/` вручную.

Значения по умолчанию задаются в `include/config.h`, сохранённые — в NVS под `cfg_*` (включая `cfg_web_enabled`). Там же хранятся последние адрес/тип/имя ELM (`last_elm*`) и результаты замера (`drag_last`, `drag_best_60/80/100`). Экран Settings на приборе показывает текущие значения и кнопку WEB, но не редактирует сами поля.

## Известные ограничения

- На экране настроек пока только девять параметров (см. `docs/SETTINGS.md`); редактирование доступно в вебе при включённом AP.
- Единицы измерения зафиксированы: `km/h` и `°C`.
- Нет фильтрации выбросов и явного таймаута данных.
- Не все мотоциклы отдают одинаковый набор PID; для Honda Dunk AF78 используется переходник Honda 4-pin → OBD2.
- Дешёвые клоны ELM327 могут выдавать `>` раньше, чем реально готовы к следующей команде; при таймауте или ответе без `41 0C` пауза между запросами автоматически увеличивается.
- Частота обновления показаний ограничена самим адаптером и протоколом KWP: обычно 5–10 Гц для оборотов/скорости, напряжение — раз в 2 с.
