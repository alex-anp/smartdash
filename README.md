# SmartDash — цифровой прибор Honda Dunk AF78 на ESP32-S3

## Описание

SmartDash — компактный дополнительный прибор для мотоцикла на базе платы **JC3636W518C** (ESP32-S3, круглый IPS-дисплей 360×360, ёмкостный тач). Прибор подключается по Bluetooth LE к ELM327-совместимому адаптеру, считывает данные OBD-II и отображает скорость, обороты, температуру и напряжение в круглом интерфейсе.

Текущее состояние зафиксировано: сплошная дуга оборотов с отдельной внутренней шкалой. Это рабочая версия интерфейса, к которой пришли после нескольких итераций по сегментам и рискам.

## Статус реализации

- [x] Инициализация дисплея ST77916 (QSPI) и тача CST816S (I²C)
- [x] Полноэкранный буфер в PSRAM — отрисовка без мерцания
- [x] Одноразовая стартовая анимация вместо бесконечного демо
- [x] Сплошная дуга RPM 0–12000 с зонами 8000 / 10000 об/мин
- [x] Отдельная внутренняя шкала: риски каждые 1000, цифры каждые 2000 об/мин
- [x] Скорость 0–99 крупными семисегментными цифрами; `0` всегда по центру
- [x] Температура и напряжение с цветовой индикацией
- [x] Индикатор ELM: три мигающие точки при поиске, `ELM OK` при подключении
- [x] BLE ELM327: поиск, автоподключение к последнему устройству, инициализация и опрос
- [x] Экран **ELM Connect**: список найденных адаптеров, RSSI, подключение по тапу (устройства отсортированы по убыванию RSSI)
- [x] Навигация свайпами/кнопкой по кругу: Dash → ELM Connect → Drag → Dash
- [x] Экран замера разгона с места: ожидание холостых 1500–2500 об/мин, таблица 10–100 км/ч, демо-режим без ELM
- [x] Последний и лучший замер сохраняются в NVS и пишутся в журнал подключений
- [x] Wi-Fi AP и базовая веб-страница (пока заглушка)
- [ ] Полноценный веб-интерфейс настроек (единицы, RPM, зоны) — параметры пока задаются в `include/config.h`
- [ ] Фильтрация выбросов и таймаут обновления данных
- [ ] Проверка с реальным ELM327 на мотоцикле

> Проверка с подключённым ELM на мотоцикле не выполнялась: адаптер отсутствовал. Без ELM прошивка работает стабильно, повторяет поиск каждые несколько секунд и показывает нули после стартовой анимации.

## Целевая платформа

| Параметр | Значение |
|---|---|
| Плата | JC3636W518C / ESP32-S3 Display Module |
| MCU | ESP32-S3R8, 240 МГц, Wi-Fi + BLE 5.0 |
| Дисплей | 1.8" круглый IPS, 360×360, ST77916, QSPI |
| Тач | CST816S, I²C, адрес `0x15` |
| Питание | Type-C (на мотоцикле — через DC/DC 12 В → 5 В) |
| Мотоцикл | Honda Dunk AF78 |
| Диагностика | Honda 4-pin → OBD2 переходник → BLE ELM327 |
| Красная зона | 8000 об/мин |
| Максимум шкалы | 12000 об/мин |

ESP32-S3 **не поддерживает Bluetooth Classic**, поэтому нужен именно BLE-совместимый ELM327.

## Что отображается

### Обороты

Внешняя дуга — сплошная, без сегментных просветов:

- угол: от **150°** до **390°** (240° всего);
- радиусы: **160–176 px**;
- подложка: тёмно-серый `0x2104`;
- зоны закраски:
  - `0–8000` — зелёный;
  - `8000–10000` — оранжевый;
  - `10000–12000` — красный.

Внутренняя шкала отделена от дуги и не перегружает отображение:

- тонкая опорная дуга радиусом **150 px**;
- риски каждые **1000 об/мин**, радиусы **138–150 px**;
- подписи каждые **2000 об/мин**: `0, 2, 4, 6, 8, 10, 12`;
- подписи означают тысячи об/мин.

### Скорость

- диапазон **0–99 км/ч**;
- крупные семисегментные цифры белым цветом, неактивные сегменты — тёмно-серые;
- значения `0–9` рисуются **одной цифрой по центру**, поэтому `0 км/ч` не смещается влево;
- подпись единиц — `km/h`.

### Температура и напряжение

Внизу экрана две колонки с иконками:

| Параметр | Условие | Цвет |
|---|---|---|
| Охлаждающая жидкость | `< 60 °C` | голубой |
| | `60–90 °C` | зелёный |
| | `> 90 °C` | красный |
| Напряжение | `< 11 В` | красный |
| | `11–12 В` | оранжевый |
| | `12–15 В` | зелёный |
| | `> 15 В` | красный |

Если данных нет, показывается `--C` и `--.-V`.

### Стартовая анимация и статус ELM

При включении, если ELM ещё не подключён, выполняется **один** пробег:

- RPM: `0 → 12000 → 0`;
- скорость: `99 → 0`;
- температура: `99 → 0` шагом 5;
- напряжение: `16.0 → 0` шагом 0.5 В.

Затем все значения остаются нулями до данных от ELM. Данные от реального адаптера немедленно перекрывают анимацию.

В нижней части экрана:

- при подключении — зелёная надпись `ELM OK`;
- без подключения — `ELM` и три оранжевые точки, загорающиеся по очереди;
- рамка вокруг индикатора отсутствует.

## Управление

| Действие | Результат |
|---|---|
| Свайп снизу вверх | Следующий экран: Dash → ELM Connect → Drag → Dash |
| Свайп сверху вниз | Предыдущий экран |
| Кнопка BOOT | Следующий экран |
| Тап по `Scan` | Повторный поиск BLE-устройств |
| Тап по устройству в списке | Подключиться к выбранному ELM327 |
| Тап по заголовку на экране Drag | Цель 60 / 80 / 100 км/ч и новый замер |

Свайп определяется во время движения пальца: порог 60 px, длительность до 1 с, приоритет вертикального направления. После обработанного свайпа тап подавляется, чтобы случайное нажатие не меняло состояние.

Экран **Drag** включается сразу при входе: сначала ждёт устойчивые холостые (1500–2500 об/мин не менее 0.8 с), затем ловит резкий рост оборотов вместе с началом движения. Время отмечается по `millis()` в BLE-задаче, пересечение каждой отметки 10 км/ч ищется интерполяцией между сэмплами. Если ELM не подключён, экран работает на синтетической рампе — так таблицу можно проверить без мотоцикла.

## BLE и ELM327

Вся BLE-работа вынесена в отдельную задачу FreeRTOS `elmTask` на **core 0**. Основной цикл (`loop()`) занимается только UI и веб-сервером, поэтому сканирование и подключение не замораживают экран и тач.

### Последовательность инициализации ELM

```
ATZ
ATE0
ATL0
ATS0
ATH0
ATSP5   -> 0100   (ISO 14230-4 KWP, fast init)
ATSP4   -> 0100   (ISO 14230-4 KWP, slow init / 5 baud)
ATSP0   -> 0100   (автоопределение, запасной вариант)
```

Следующий протокол пробуется только если `0100` не вернул ответ `41 ...` (`STOPPED`, `ERROR`, `NO DATA` или таймаут). `ATZ` получает таймаут 2.5 с, базовые AT-команды — 1.2 с, `0100` — 6–8 с, поскольку KWP-инициализация у клонов ELM327 идёт медленно. Адрес сохраняется в NVS только после подтверждённого `0100`.

### Цикл опроса

Команды чередуются каждые 120 мс:

```
010C  -> RPM       = (A * 256 + B) / 4
010D  -> Speed     = A
0105  -> Coolant   = A - 40
ATRV  -> Voltage   = число из ответа, принимается 5–20 В
```

Ответы парсятся по hex-шаблону `41 <PID>`; на экране остаётся последнее удачно полученное значение.

### Подключение

- Имя устройства считается совместимым, если содержит `OBD`, `ELM`, `V-LINK`, `VEEPEAK`, `OBDLINK` или `VGATE`.
- Дополнительно проверяются UUID `FFF0`, `FFE0`, `6E400001`.
- Для UART-профиля ищутся `FFF1`/`FFF2` или Nordic UART Service.
- Адрес успешного устройства сохраняется в NVS (`smartdash` / `last_elm`).
- При старте сохранённый адрес используется для autoconnect; если его нет — запускается сканирование.
- При потере связи поиск перезапускается с интервалом 3 с; после трёх неудач подключения к сохранённому MAC (`setConnectTimeout` в NimBLE задаётся в мс) прошивка переходит к поиску любого совместимого адаптера.

`rxBuf` и список найденных устройств защищены мьютексами, так как обновляются из BLE-задачи, а читаются из UI. Список `found` хранится отсортированным по убыванию RSSI: при каждом обновлении запись сдвигается вверх или вниз, поэтому первые строки экрана — всегда устройства с самым сильным сигналом.

### Журнал подключений

Журнал пишется в файл на флэше (LittleFS, раздел `spiffs` из `default_16MB.csv`), поэтому спокойно переживает поездку, выключение питания и перезагрузку. Текущий файл `/elm.log` растёт до **1 МБ** (~5–6 тыс. строк), затем становится `/elm.prev.log`, и начинается новый файл — суммарно хранится до ~2 МБ истории. Формат строки: `b<номер загрузки> t<секунды>.<мс> <событие>`. Пишутся `BOOT`, `SCAN`, `MATCH`, `CONNECT`, `GATT`, `CHARS`, `AT`, `PROTO`, `INIT`, первые 8 ответов опроса и неудачи по сохранённому MAC.

Просмотр после возвращения к ПК:

- **По USB:** подключитесь, откройте монитор порта (115200) и введите `log` — последние 16 КБ; `log all` — весь журнал; `clear` — очистить. При старте печатается подсказка. Чтение идёт порциями, поэтому запись новых событий не блокируется надолго.
- **По Wi-Fi:** `http://192.168.4.1/elm-log` — хвост 32 КБ, `http://192.168.4.1/elm-log?all=1` — весь файл, `?clear=1` — очистить.

Номер загрузки `bN` позволяет отличить события до и после перезапуска. Журнал не зависит от `SMARTDASH_SERIAL_DEBUG`: он пишется всегда и остаётся в файле даже если питание выключилось сразу после события.

## Архитектура ПО

```
smartdash/
├── platformio.ini        #Конфигурация PlatformIO
├── include/
│   ├── config.h          # Пины, константы экрана и мотоцикла
│   ├── display.h         # Интерфейс LovyanGFX
│   ├── dragrace.h        # Конечный автомат замера разгона
│   ├── elm327.h          # Публичный API BLE/ELM
│   ├── storage.h         # NVS + журнал на LittleFS
│   ├── ui.h              # Данные дашборда и UI-API
│   └── web.h             # Wi-Fi AP / WebServer
├── src/
│   ├── main.cpp          # setup()/loop()
│   ├── display.cpp       # Настройка ST77916, подсветки и CST816S
│   ├── dragrace.cpp      # Холостые -> старт -> отметки 10 км/ч -> результат
│   ├── elm327.cpp        # BLE-задача, AT-команды, парсинг PID
│   ├── storage.cpp       # Последний ELM, замеры, журнал подключений
│   ├── ui.cpp            # Рендер, анимация, тач/свайпы, экраны
│   └── web.cpp           # Точка доступа и базовый HTTP-маршрут
├── docs/                 # Заметки по разработке
└── README.md
```

Потоки данных:

```
ELM327 (BLE) -> elmTask (core 0) -> DashData+t_ms -> snapshot -> ui_loop() (core 1) -> PSRAM sprite -> display
                                      \-> dragrace.cpp (сэмплы, отметки, результат) -> NVS/журнал
```

Статические элементы шкалы рисуются один раз. Динамические элементы перерисовываются только при изменении значения (для напряжения — с порогом 0.05 В). Экран ELM Connect обновляется не чаще одного раза в 600 мс, так как полный вывод спрайта занимает около 50 мс.

## Сборка и прошивка

```bash
# Сборка
~/.platformio/penv/bin/pio run

# Сборка + заливка (порт определяется автоматически)
~/.platformio/penv/bin/pio run -t upload
```

Порт обычно `/dev/ttyACM0`. Если Linux не видит устройство пользователю, нужен `dialout` или правила udev PlatformIO.

Логирование по умолчанию отключено: `Serial.printf` через USB CDC иногда блокировал задачу почти на 800 мс. Чтобы включить логи, добавьте в `build_flags` в `platformio.ini`:

```
-DSMARTDASH_SERIAL_DEBUG=1
```

`pio device monitor` требует интерактивного терминала; при перенаправлении вывода используйте любой обычный последовательный монитор.

## Известные ограничения

- Веб-интерфейс настройки пока не реализован полностью.
- Единицы измерения зафиксированы: `km/h` и `°C`.
- Нет фильтрации выбросов и явного таймаута данных.
- Не все мотоциклы отдают одинаковый набор PID; для Honda Dunk AF78 используется переходник Honda 4-pin → OBD2.
- Дешёвые клоны ELM327 могут отвечать с задержками.
- Работа с реальным адаптером на мотоцикле требует отдельной проверки.
