# AGENTS.md — SmartDash

ESP32-S3 прибор Honda Dunk AF78 на PlatformIO/Arduino. Один env: `jc3636w518c`.
Подробности есть в `README.md` и `docs/SMARTDASH_DEV.md`; здесь только неочевидное.
Комментарии и документация в репозитории — на русском.

## Сборка, прошивка, проверка

- `pio` **не в PATH**. Использовать полный путь:
  - сборка: `~/.platformio/penv/bin/pio run -e jc3636w518c`
  - прошивка: `~/.platformio/penv/bin/pio run -e jc3636w518c -t upload`
- Порт определяется автоматически (macOS: `/dev/cu.usbmodem*`).
- Тестов, CI, линтеров и task-runner нет (`test/` пуст). Проверка = успешная сборка;
  поведение на железе проверяется отдельной прошивкой.
- **Не заливать на плату и не коммитить без явной просьбы пользователя** — перед этим
  он каждый раз даёт отдельное разрешение.

## Потоки и порядок инициализации

- BLE (скан, коннект, GATT discovery, AT-init, опрос OBD) живёт в `elmTask` на **core 0**.
  `loop()` (UI + web + USB Serial) — на core 1 и не должен ждать радио-операций.
- Публичные `elm_*()` только выставляют volatile-флаги; разбирает их `elm_loop()`.
  Не вызывать NimBLE API из UI/web: блокировки до сотен мс замораживают тач.
- Порядок `setup()`: `storage_init` → display → ui → web → elm. Менять нельзя: NVS должен
  быть открыт до чтения сохранённого адреса ELM.

## Диагностика (не через Serial)

- `Serial.printf` по USB CDC блокирует ~800 мс, поэтому `SD_LOG` по умолчанию no-op;
  включать только `-DSMARTDASH_SERIAL_DEBUG=1` в `build_flags`.
- Постоянный журнал — LittleFS `/elm.log` + `/elm.prev.log`, ротация при 1 МБ,
  префикс строки `bN tS.mmm`. Пишется всегда, независимо от дебага.
  Чтение: USB Serial `log` / `log all` / `clear`; HTTP `/elm-log`, `?all=1`, `?clear=1`.
- NVS namespace `smartdash`: `last_elm`, `last_elm_type`, `drag_last`,
  `drag_best_60/80/100`. Старый общий `drag_best` переносится только при совпадении цели.
- Пины и константы — только в `include/config.h`; веб-страница `/` пока заглушка.

## BLE/ELM: проверенные грабли

- ESP32-S3 не имеет Bluetooth Classic — нужен BLE-ELM327.
- Полный GATT discovery обязателен. Приоритет характеристик: `FFF1=Notify / FFF2=Write`;
  для Vgate/iCar — профиль `18F0` (`write=2AF1`, `notify=2AF0`).
  Fallback `write=0x2a00` / `notify=0xfff1` **не работает**: AT-команды не доходят
  и инициализация висит на `Initializing ELM...`.
- Сначала пробуется адрес из NVS с типом адреса, ретраи 2→60 с; после трёх неудач —
  поиск любого совместимого адаптера.
- Сканирование/подключение идёт в фоне независимо от того, открыт экран ELM Connect
  или нет; повторный scan запускается только тапом `Scan`, не входом на экран.

## UI и замер разгона

- Навигация по осям: свайп вверх — открыть ELM Connect, вниз — закрыть к предыдущему
  экрану, влево/вправо — Dash↔Drag. BOOT переключает Dash/Drag и закрывает ELM.
- `src/dragrace.cpp`: холостые 1500–2500 об/мин 800 мс → скачок оборотов лишь
  подтверждает старт, отсчёт идёт от интерполированного пересечения 3 км/ч
  (защита от газовки на месте).
- Сэмпл `DashData::t_ms` = середина интервала запрос→ответ (`t_tx_ms`/`t_rx_ms`),
  а не время парсинга. Сырые сэмплы пишутся в журнал строками `DRAG S ...`;
  лучший результат хранится отдельно для каждой цели.
