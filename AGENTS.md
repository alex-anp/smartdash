# AGENTS.md — SmartDash

ESP32-S3 прибор Honda Dunk AF78 на PlatformIO/Arduino. Один env: `jc3636w518c`.
Подробности есть в `README.md` и `docs/SMARTDASH_DEV.md`; здесь только неочевидное.
Комментарии и документация в репозитории — на русском.

## Сборка, прошивка, проверка

- `pio` **не в PATH**. Использовать полный путь:
  - сборка: `~/.platformio/penv/bin/pio run -e jc3636w518c`
  - прошивка: `~/.platformio/penv/bin/pio run -e jc3636w518c -t upload`
- Порт определяется автоматически (macOS: `/dev/cu.usbmodem*`, Linux: `/dev/ttyACM0`).
  На Linux группа `dialout` есть в `/etc/group`, но в текущей сессии её может не быть:
  при `Permission denied` прошивать через `sg dialout -c '~/.platformio/penv/bin/pio run -e jc3636w518c -t upload'`.
- Тестов, CI, линтеров и task-runner нет (`test/` пуст). Проверка = успешная сборка;
  поведение на железе проверяется отдельной прошивкой.
- Предупреждения LovyanGFX про deprecated `drawString` при сборке — ожидаемы, не ошибки.
- Коммиты сразу пушатся в `origin/main`. Статус смотреть через `git status -sb`:
  git здесь старый, `git branch --show-current` не поддерживается.
- **Не заливать на плату и не коммитить без явной просьбы пользователя** — перед этим
  он каждый раз даёт отдельное разрешение.

## Потоки и порядок инициализации

- BLE (скан, коннект, GATT discovery, AT-init, опрос OBD) живёт в `elmTask` на **core 0**.
  `loop()` (UI + web + USB Serial) — на core 1 и не должен ждать радио-операций.
- Публичные `elm_*()` только выставляют volatile-флаги; разбирает их `elm_loop()`.
  Не вызывать NimBLE API из UI/web: блокировки до сотен мс замораживают тач.
- Порядок `setup()`: `storage_init` → display → ui → web → elm. Менять нельзя: NVS должен
  быть открыт до чтения сохранённого адреса ELM.

## Диагностика (не через Serial)

- `Serial.printf` по USB CDC блокирует ~800 мс, поэтому `SD_LOG` по умолчанию no-op;
  включать только `-DSMARTDASH_SERIAL_DEBUG=1` в `build_flags`.
- Постоянный журнал — LittleFS `/elm.log` + `/elm.prev.log`, ротация при 1 МБ,
  префикс строки `bN tS.mmm`. Пишется всегда, независимо от дебага.
  Чтение: USB Serial `log` / `log all` / `clear`; HTTP-страница `/log` и текст
  `/elm-log`, `?all=1`, `?clear=1` (после очистки — редирект на `/log?cleared=1`).
- NVS namespace `smartdash`: `last_elm`, `last_elm_type`, `drag_last`,
  `drag_best_60/80/100`, плюс пользовательские `cfg_*` из `src/settings.cpp`
  (включая `cfg_web_enabled` — состояние кнопки WEB, дефолт выключено).
  Старый общий `drag_best` переносится только при совпадении цели.
- Пины и константы — только в `include/config.h`. Веб AP в одном стиле отдаёт корень
  `/` с кнопками SETTINGS / ELM LOG, форму `/settings` (POST + PRG-редирект) и страницу
  журнала `/log` (текст — `/elm-log`); `DNSServer` в режиме catch-all плюс редирект
  probing-путей дают captive portal — телефон сам открывает корень.
  WEB поднимают/опускают кнопкой на экране Settings: `web_set_enabled()` останавливает
  сервер, DNS и радио, состояние пишется в `cfg_web_enabled` и восстанавливается при
  загрузке. Экран Settings показывает текущие значения и кнопку WEB, поля правит веб.
  Дефолты — в `config.h`, сохранение — в NVS под `cfg_*`. Инвентарь — `docs/SETTINGS.md`.

## BLE/ELM: проверенные грабли

- ESP32-S3 не имеет Bluetooth Classic — нужен BLE-ELM327.
- Полный GATT discovery обязателен. Приоритет характеристик: `FFF1=Notify / FFF2=Write`;
  для Vgate/iCar — профиль `18F0` (`write=2AF1`, `notify=2AF0`).
  Fallback `write=0x2a00` / `notify=0xfff1` **не работает**: AT-команды не доходят
  и инициализация висит на `Initializing ELM...`.
- Сначала пробуется адрес из NVS с типом адреса, ретраи 2→60 с; после трёх неудач —
  поиск любого совместимого адаптера.
- Сканирование/подключение идёт в фоне независимо от того, открыт экран ELM Monitor
  или нет; повторный scan запускается только тапом `Scan`, не входом на экран.
- Экран ELM Monitor до инициализации показывает список найденных устройств, после
  `INIT_DONE` — данные активного адаптера (`elm_get_connected()`): имя, MAC, тип адреса,
  протокол, RSSI и uptime. Имя сохраняется в NVS (`last_elm_name`); при подключении
  по сохранённому MAC RSSI неизвестен (-127). Тапы по списку при подключении игнорируются.
- Опрос разделён: `010C0D` (обороты+скорость) — основной; `0105` и `ATRV` чередуются
  раз в секунду. Паузы после ответа нет: `>` уже означает готовность, следующий запрос
  уходит на такте `elmTask` (~2 мс). Если клон отвечает по таймауту или без `41 0C`,
  пауза растёт 8→…→120 мс и медленно уменьшается после серии чистых ответов.
  Откат на `010C/010D/0105/ATRV` — только при паузе 120 мс и трёх ответах без `41 0C`.
  Не возвращать фиксированную паузу после каждого запроса и не ставить температуру
  в общий пакет — это главная причина «скачков» показаний.

## UI и замер разгона

- Навигация по осям: с Dash свайп вверх — ELM Monitor, вниз — экран настроек;
  с ELM вниз — назад, с настроек вверх — назад. Влево/вправо — Dash↔Drag.
  На Drag вертикальные свайпы игнорируются. BOOT переключает Dash/Drag и
  закрывает модальные экраны. Настройки редактируются только веб-формой в
  `web_loop()` (та же UI-задача), пишутся в NVS и через `ui_settings_changed()`
  заставляют `ui_loop()` перерисовать статику целиком; `elmTask` их не читает.
- Дашборд обновляется инкрементально: дуга RPM заливается только в изменившемся
  интервале, на панель через `setClipRect()` + `pushSprite()` уходят только «грязные»
  прямоугольники. Полный кадр — только при смене экрана. Не вызывать `flush()` на
  каждый тик данных: это полные 252 КБ из PSRAM по QSPI.
- `src/dragrace.cpp`: холостые 1500–2500 об/мин 800 мс → скачок оборотов лишь
  подтверждает старт, отсчёт идёт от интерполированного пересечения 3 км/ч
  (защита от газовки на месте).
- Сэмпл `DashData::t_ms` = середина интервала запрос→ответ (`t_tx_ms`/`t_rx_ms`),
  а не время парсинга; для таймаутов и служебных снимков midpoint не применяется.
- Сырые сэмплы пишутся в журнал только от Armed до финиша:
  `DRAG S t=<ms> tx=<ms> rx=<ms> rpm=<n> spd=<kmh>` — по ним можно пересчитать
  замер с другими порогами. Итог — `DRAG <target>,...`; best — отдельно на каждую цель.

## Внешний референс

- `erdemerciyas/ESP32-S3-OBD2` (AURA v1.2.1): их ROLL — не бортовой таймер, а поток
  телеметрии + анализ на Android (GNSS телефона + IMU QMI8658). На ESP нет ни таймслипы,
  ни обратного отсчёта; результат считает приложение.
- Переносимые идеи уже внедрены: midpoint `tx/rx`, сырая скорость без EMA, best per target.
  Приложение для телефона не планируется — phone-bridge и синхронизацию часов не портировать.
  GNSS/IMU-слияние, автокалибровка OBD по GPS и уклон без доп. датчиков не переносятся;
  реалистичная точность OBD-only — около ±0.2–0.5 с.
